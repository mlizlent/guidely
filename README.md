# Guidely

Guidely is a RAG (Retrieval-Augmented Generation) based internal knowledge
assistant. Upload company documents, ask questions in natural language, and get
grounded answers sourced from your own content.

## Architecture

```
┌─────────────┐     HTTP      ┌──────────────────────────┐
│  React SPA   │◄──────────────►│  FastAPI (uvicorn)        │
│  (Vite +     │                │  /documents, /search/ask  │
│   Tailwind)  │                │                            │
└─────────────┘                │  core/                     │
                               │  services/                 │
                               │   • chunker                │
                               │   • parser (.txt/.md/.pdf) │
                               │   • embedder (sentence-    │
                               │     transformers)          │
                               │   • vector_store (FAISS)   │
                               │   • retriever + answerer   │
                               │     (Groq OpenAI-compatible)│
                               └──────────────────────────┘
```

* **Embeddings** are produced locally with `sentence-transformers`
  (`all-MiniLM-L6-v2`). Vectors are L2-normalized and stored in an in-memory
  FAISS `IndexFlatIP` index.
* **Answers** are generated by Groq through an OpenAI-compatible client. Set
  `GROQ_API_KEY` in `backend/.env`.
* **Chunking** is character-based with overlap and boundary detection; chunks are
  content-hashed so unchanged text is never re-embedded.

## Quick start

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env           # fill in GROQ_API_KEY
uvicorn main:app --reload
```

The server runs on `http://localhost:8000` and exposes:

| Method | Path                       | Description                          |
| ------ | -------------------------- | ------------------------------------ |
| GET    | `/health`                  | Liveness check                       |
| GET    | `/metrics`                 | Document / chunk / query stats       |
| POST   | `/documents/upload`        | Upload a `.txt`, `.md`, or `.pdf`    |
| POST   | `/documents/reindex`       | Re-parse & re-embed all uploads      |
| GET    | `/documents`               | List indexed documents               |
| GET    | `/documents/{doc_id}`      | Get a single document                |
| GET    | `/documents/{doc_id}/embeddings` | List chunks + vectors for a doc |
| PUT    | `/documents/{doc_id}`      | Replace a document's file            |
| DELETE | `/documents/{doc_id}`      | Delete a document and its vectors    |
| POST   | `/search/ask`              | Ask a question (`{"question": "..."}`) |

### Frontend

```bash
cd frontend
npm install
npm run dev
```

The UI opens at `http://localhost:5173` and provides four pages:

* **Documents** — upload, filter by tag, view content, edit, delete.
* **Search** — ask questions, see the generated answer and source snippets.
* **Indexing** — trigger re-indexing of stale or all documents.
* **Metrics** — live system health, document/chunk counts and latency.

## Configuration

All settings live in `backend/.env` (see `backend/.env.example`):

| Variable              | Default                        | Purpose                          |
| --------------------- | ------------------------------ | -------------------------------- |
| `GROQ_API_KEY`        | *(required)*                   | Groq API key for answer generation |
| `GROQ_BASE_URL`       | `https://api.groq.com/openai/v1` | Groq OpenAI-compatible endpoint  |
| `CHAT_MODEL`          | `llama-3.3-70b-versatile`      | Chat model name                  |
| `EMBEDDING_MODEL`     | `all-MiniLM-L6-v2`             | Local embedding model            |
| `DATA_DIR`            | `./data`                       | Root data directory              |
| `TOP_K`               | `3`                            | Retrieval top-k                  |
| `CHUNK_SIZE_CHARS`     | `800`                          | Chunk window (500-1000 clamped)  |
| `CHUNK_OVERLAP_CHARS` | `100`                          | Overlap between chunks           |
| `CORS_ORIGINS`        | `localhost:5173,127.0.0.1:5173` | Comma-separated allow-list      |

## Sample data

`backend/data/sample-docs/` ships with three documents (`faq.txt`, `guide.txt`,
`policy.txt`). Copy them into `backend/data/uploads/` (or upload them through
the UI) and run `POST /documents/reindex` to make them searchable.

## Notes

* The vector store is **in-memory**; restarting the server clears the index.
* Answers are generated by an external LLM. Without `GROQ_API_KEY` the
  `/search/ask` endpoint returns `504 MODEL_TIMEOUT`.
* The frontend `api.js` normalizes backend responses into the shape the UI
  expects, with sensible defaults for fields the backend does not track yet
  (status, tags, timestamps, size).
